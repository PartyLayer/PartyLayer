## What is PartyLayer?

PartyLayer connects Canton dApps to supported wallets through a shared TypeScript API and CIP-0103 integrations. React applications get wallet selection, connection states, an account menu, themes and default **Powered by PartyLayer** attribution. Applications can also use the framework-independent SDK or Vue bindings.

Reviewed wallet runtimes are dependencies of the kit and load as needed. Developers do not install or register a PartyLayer package for each wallet. Network support, the registry channel, application credentials and each wallet's actual capabilities determine what is available.

> **Version scope:** This guide covers React **3.1.0+** / SDK **0.20.0+**. See [release validation](./docs/releasing.md#default-wallet-release-validation) for automated checks, outstanding manual/live acceptance and release status.

## Quick start

### 1. Install

In an existing React application:

```bash
npm install @partylayer/react @tanstack/react-query
```

The SDK and supported wallet runtimes come with this command. React 18+ is required. TanStack Query is a required peer; its provider is needed only when using the optional `/query` data hooks.

### 2. Mount the kit and button

```tsx
// App.tsx — in Next.js, put this inside a 'use client' component.
import { PartyLayerKit, ConnectButton } from '@partylayer/react';

export default function App() {
  return (
    <PartyLayerKit network="devnet" appName="My dApp">
      <ConnectButton />
    </PartyLayerKit>
  );
}
```

No stylesheet import or wallet-specific imports are required. The kit owns the client lifecycle and supplies theme, session and discovery context. `ConnectButton` opens the wallet picker and displays the account menu after connection. Read the connected party and network with `useAccount()`.

Follow the [complete quick start](./docs/quick-start.md) for Next.js App Router, Vite, configuration and troubleshooting.

### Starting a new app?

```bash
npm create partylayer-app@latest my-dapp -- --template react-vite --pm npm
```

The CLI creates the project and installs its dependencies. Then run `cd my-dapp` and `npm run dev`. Also available: `next-ssr`, `vue-nuxt-pinia`, `vanilla`, `react-tokenization` and `react-dvp`. See [the CLI guide](./packages/create-partylayer-app/README.md) for each template's scope.

## Coming from RainbowKit?

Read the [Canton React wallet connection guide](https://partylayer.xyz/docs/rainbowkit-for-canton) for installation, familiar UI patterns and Canton-specific requirements. PartyLayer is independent from RainbowKit; the comparison concerns developer experience, not EVM compatibility or complete feature parity.

## Wallet configuration

| Requirement | Configuration |
| --- | --- |
| Supported wallets on your network | Set `network="devnet"`, `"testnet"` or `"mainnet"` |
| Vala beta | `network="devnet" channel="beta"` |
| Send | Select `mainnet`; the catalog does not list it on Devnet |
| WalletConnect | Pass a stable `walletConnect={{ projectId: 'YOUR_PROJECT_ID' }}` configuration |
| Bron | Pass application-owned OAuth/API configuration through `bron` |
| Extend the catalog | Use `additionalAdapters` |
| Replace the catalog | Use `adapters` explicitly |

Wallet installation, hosted-wallet login, approval and test funding remain user/vendor prerequisites. Including a runtime does not create a wallet account or enable an operation the wallet does not implement.

## Usage examples

### Framework-independent TypeScript

```bash
npm install @partylayer/sdk
```

```ts
import { createPartyLayer } from '@partylayer/sdk';

const client = createPartyLayer({
  network: 'devnet',
  app: { name: 'My dApp' },
});

const wallets = await client.listWallets();
// Render your picker using these wallet IDs. In a user click handler:
// await client.connect({ walletId: selectedWallet.walletId });

const session = await client.getActiveSession();
console.log(session?.partyId);

// When this application-owned client is no longer needed:
client.destroy();
```

Popup-based connections must start from a user gesture. For React, use the default `ConnectButton` and let `PartyLayerKit` manage the client. See [Vanilla JS](https://partylayer.xyz/docs/vanilla-js) for a custom integration.

### Themes, language and attribution

```tsx
<PartyLayerKit network="devnet" appName="My dApp" theme="auto" locale="en">
  <ConnectButton />
</PartyLayerKit>
```

English is the default; Turkish is also supported. Set `direction="rtl"` explicitly for right-to-left layouts. The connection modal and generated React starters show **Powered by PartyLayer** by default. Custom UI and attribution configuration remain available. See [theming](https://partylayer.xyz/docs/theming) and [ConnectButton](https://partylayer.xyz/docs/connect-button).

## Authentication and transactions

Wallet connection establishes a wallet session. Application sign-in requires a backend-issued challenge and independent signature/key verification; use the [authentication guide](./docs/authentication.md).

Message signing does not prove a transfer or swap works. Your app or protocol constructs valid Canton commands, supplies authorized data and verifies the final ledger result. PartyLayer exposes supported wallet actions and a one-submission transaction flow with read-only reconciliation. An unknown outcome is not automatically retried.

## CIP-0103 (Canton dApp Standard) compliance

Browser-native connections use official Canton discovery as their connection owner. `client.asProvider()` exposes the connected native provider through a stable facade, including accounts, events and raw Ledger API results. Existing compatibility integrations have narrower contracts; capabilities must be checked before use.

Use the [AI integration guide](./docs/ai-integration.md) with your coding assistant.

Upgrading an existing app? Start with the [current migration guide](./docs/migration.md). Native cached sessions may require one explicit reconnect. Native `asProvider()` Ledger API results are raw JSON; migrate callers that parsed `result.response`. See [protocol ownership and migration](./docs/protocol-ownership.md) and the [CIP-0103 guide](https://partylayer.xyz/docs/cip-0103).
