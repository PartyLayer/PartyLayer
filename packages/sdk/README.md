# @partylayer/sdk

The framework-independent Canton wallet client. Discover supported wallets, connect through a shared API and use the connected wallet's capabilities. Reviewed wallet runtimes are included and load as needed.

[Documentation](https://partylayer.xyz/docs/vanilla-js) · [API reference](https://github.com/PartyLayer/PartyLayer/blob/main/docs/api.md) · [Wallets](https://partylayer.xyz/wallets)

> This checkout targets the unpublished **0.20.0** candidate. Until publication, npm `@latest` remains the previous release. See the repository's [release status](https://github.com/PartyLayer/PartyLayer/pull/343).

## Installation

```bash
npm install @partylayer/sdk
```

React apps should use the ready-made kit instead. This single command includes the SDK and wallet runtimes:

```bash
npm install @partylayer/react @tanstack/react-query
```

See [the React quick start](https://partylayer.xyz/docs/quick-start). No separate PartyLayer wallet packages are required.

## Quick start

```ts
import { createPartyLayer } from '@partylayer/sdk';

const client = createPartyLayer({
  network: 'devnet',
  app: { name: 'My dApp' },
});

const wallets = await client.listWallets();
for (const wallet of wallets) {
  console.log(wallet.walletId, wallet.name, wallet.capabilities);
}

// Render these entries in your picker. Start connect from its click handler:
// await client.connect({ walletId: selectedWallet.walletId });

client.on('session:connected', ({ session }) => {
  console.log('Party:', session.partyId);
  console.log('Capabilities:', session.capabilitiesSnapshot);
});

// Read current/restored state; a cache alone does not establish a live connection.
const session = await client.getActiveSession();
console.log(session?.partyId);
```

Use one client for the lifetime of your application integration. Call `await client.disconnect()` for an explicit logout and `client.destroy()` when disposing an application-owned client. `PartyLayerKit` handles client disposal for React.

## Configuration

```ts
const walletConnect = { projectId: 'YOUR_PROJECT_ID' };

const client = createPartyLayer({
  network: 'devnet',
  app: { name: 'My dApp' },
  channel: 'stable',
  walletConnect,
});
```

| Option | Effect |
| --- | --- |
| `network` | Required: `devnet`, `testnet` or `mainnet`; filters the catalog |
| `app.name` | Required: application name presented during connection |
| `channel` | `stable` by default; `beta` on Devnet includes Vala |
| `walletConnect` | Project ID and optional pairing metadata; omitted means hidden |
| `bron` | Application-owned OAuth/API configuration; omitted means hidden |
| `additionalAdapters` | Extends the included catalog |
| `adapters` | Replaces the included catalog |
| `registryUrl` | Defaults to `https://registry.partylayer.xyz` |

Hosted wallets require the user's own login and approval. Send is Mainnet-only in the catalog. See [configuration and wallet limits](https://partylayer.xyz/docs/wallets).

## Message signing and authentication

Call `signMessage` only when the connected session supports it:

```ts
const session = await client.getActiveSession();
if (session?.capabilitiesSnapshot.includes('signMessage')) {
  const result = await client.signMessage({ message: 'Hello, Canton!' });
  console.log(result.signature);
}
```

A returned signature is not a server login. Authentication needs a backend-generated challenge, single-use nonce, origin binding and independent verification against an authorized party key. See [authentication](https://partylayer.xyz/docs/authentication).

## Transactions

There is no universal sign-then-submit sequence across Canton wallets. Some wallets combine approval and submission; others expose a separate signing operation or native CIP-0103 `prepareExecute`. Inspect capabilities and follow the wallet's command contract.

Your app constructs valid commands and independently confirms ledger settlement. A command ID, a resolved Promise or message signature is not proof of a successful transfer/swap. Uncertain outcomes must be reconciled without automatically submitting again. See [transaction lifecycle](https://partylayer.xyz/docs/transaction-lifecycle) and [token transfers](https://partylayer.xyz/docs/token-transfers).

## Native CIP-0103 provider and migration

Use `client.asProvider()` for the connected provider surface. Native connections use official Canton discovery and forward native accounts, events and Ledger API requests through a stable facade. Native Ledger API responses are **raw JSON**. Existing `client.ledgerApi()` and explicit `createProviderBridge(client)` compatibility paths retain their documented wrapper/limits.

Existing native caches without the official provider hint need one explicit reconnect. Restored state must agree with the wallet's live party, network, origin and expiry. See [protocol ownership and migration](https://github.com/PartyLayer/PartyLayer/blob/main/docs/protocol-ownership.md).

## Errors and cleanup

Handle user rejection, unavailable wallets, timeouts, network mismatch and unsupported capabilities as separate application states. Do not silently retry a ledger write after an ambiguous error. See [error handling](https://partylayer.xyz/docs/error-handling).

`client.on(event, handler)` returns an unsubscribe function. Release subscriptions and destroy clients you create when their owner is disposed. Never call `destroy()` on the client managed by a still-mounted React kit.
